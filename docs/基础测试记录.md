## 原测试脚本检查

`tools/verify.js` 是手写 CDP 验收工具，不是 Playwright。静态统计有 40 处 report 调用，其中真实 PDF 分支依赖 WSA_RESUME；README 的“35 项”与当前源码不一致。其覆盖项包含扩展加载、默认档案、mock 页、持久化、扫描件判定、导入校对、无 Key 错误、CSV 和粗粒度安全正则。

本阶段**未直接执行**该脚本：freeCdpPorts/freeServerPorts 会不核实所有权就按固定监听端口 taskkill，且清理固定 profile 目录。为避免影响用户现有服务，不启动这一整套有副作用的历史验收；先建立可重复且无该副作用的基础测试。新 Playwright 体系应只管理自己创建的资源，不把旧脚本直接套壳。

`tools/debug-ui.js` 也有固定端口强杀及 profile 清理，未执行。图标/PDF 生成工具会覆盖现有资源，ZIP 工具会写 dist，分析阶段不需要执行，已做源码与语法检查。

## 未验证范围与已知缺口

- 14 项通过仅是基础基线：Chrome API 使用内存桩，DOM 填充、真实 sidePanel、IndexedDB、真实 React/Vue 和 ATS 行为尚未运行浏览器验证。
- 未进行真实 API 联通、模型成功解析、DOCX、学习流程、加密凭据、备份往返或版本迁移验收；后四类核心能力当前尚不存在或不完整。
- 旧 react-mock 是手写受控模拟，Moka/国聘也为本地仿制页，不能证明真实网站兼容率。
- 源码审查发现毕业时间 key 不一致、明文 Key、整体覆盖存储、未知字段被忽略等问题，基础测试通过不表示这些问题已修复；详见《重构方案》。
- 内置 PDF.js 版本落在官方 CVE-2024-4367 受影响范围；本次解析测试显式设置 isEvalSupported:false，但生产两处解析入口尚未修改。未进行漏洞利用测试。
- 本阶段新增测试与文档都属于源码，不需新增忽略项；已有 dist 和日志忽略规则保持不变。后续新增 npm/Playwright 产物时再同步 .gitignore。
