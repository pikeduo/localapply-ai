# 悬浮卡片、自动页面识别与本地诊断验收

日期：2026-10-25。源码起点 `b4d1e26`，本轮未暂存、提交或推送。仅落实用户新增的三项需求，不视为阶段四全面重构完成。

## 实际行为

- 自动在本机检查可见控件元数据、页面标题，识别招聘表单并显示右上角提示及工具栏“表单”标记。支持动态插入和显隐变化；不读取输入值、不授予详细扫描权限、不调用模型。登录短表不显示网申提示；无法识别时仍可点击工具栏手动打开。
- 点击工具栏或提示，在网页右上角打开独立扩展卡片，只有“自动填充 / 简历预览”两个页签，不再打开浏览器侧栏。关闭可收起，再点击工具栏打开。
- 自动填充复用阶段三全部确认流程、填写回读和映射管理；简历预览按当前档案展示已确认字段与多段经历，敏感资料默认遮挡，提供刷新、编辑入口；编辑和文件导入仍在设置页完成。
- 卡片底部及扩展设置页提供日志查看、导出、确认清空。记录操作时间、类型、耗时、数量、填写成功/失败统计、错误分类、HTTP 状态及可用的插件代码位置。固定白名单排除原始错误正文、个人值、Key、网页标签与完整 URL。

## 数据和授权

- 个人库仍为 Schema v3，未改变简历解析、密钥管理、字段学习核心或备份格式，未增加依赖。
- `localapply.diagnostics`：独立 `chrome.storage.local` 日志，最多 400 条，读取和后续写入过滤七天前记录；不进入个人资料备份，可手动清空。文件独立模式不访问扩展日志。
- `localapply.panelSessions`：短期 `chrome.storage.session` 会话，绑定标签、完整 URL、文档 ID、随机令牌与 30 分钟期限；后台休眠后可恢复，关闭/刷新/导航后拒绝旧访问。完整 URL 只用于会话校验，不写入诊断日志。
- 卡片使用封闭 Shadow DOM 中的扩展 iframe，资料不放进招聘页面 DOM；后台逐请求验证令牌，伪造 iframe 和内容脚本不能读取个人库或日志。没有向网页开放 postMessage 私有代理。
- 新接口：`panel:context`、`panel:close`、`diagnostics:read`、`diagnostics:clear`（需确认）、`diagnostics:uiError`。内容脚本仅可上报分类/数量和固定检测错误事件。

## 手动验证与限制

1. 在扩展管理页点击“重新加载”，刷新已打开招聘页和设置页，无需卸载。
2. 在设置页录入合成资料；可在项目目录执行 `python -m http.server 8765 --bind 127.0.0.1`，手动打开 `http://127.0.0.1:8765/test-pages/phase3-application.html`。
3. 等待右上角网申提示，点击打开；或点击工具栏图标。确认两个页签，授权扫描，选择单项/批量预览，核对后确认填写和验证结果。
4. 打开简历预览，检查当前档案、默认遮挡和编辑/刷新入口；展开日志并导出。清空需确认，不影响资料或 Key。
5. 刷新或导航后重新授权；登录短表不提示。关闭后可通过工具栏再次打开。

自动识别为启发式判断，尚未在真实北森、Moka、飞书站点抽检；复杂跨域 iframe、封闭组件或页面策略可能需要单独适配。当前只支持普通 HTTP(S) 招聘网页卡片，浏览器内部页及 file:// 不注入；file:// 独立设置功能继续保留。不能将模拟通过等同于真实站点或先前 sub2api HTTP 502 已解决。

下一步建议：先按以上步骤手动验证，再基于出现漏检或控件失败的具体真实页面开展定向适配。本轮在此停止。
