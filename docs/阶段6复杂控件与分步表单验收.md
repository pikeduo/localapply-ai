# 阶段六：复杂控件与分步表单

基准：DEVELOPMENT_PLAN.md v2.0，2026-10-29 用户授权推进。Schema v5 不变，无新增依赖；不创建分支，不提交或推送，不进入阶段七。

## 本轮实现

- 扫描优先识别原生 select/textarea；原生 select 即使带 combobox 角色，也使用原生选项和真实状态验证。
- 外壳与内部输入都声明 combobox、且明确关联同一列表时，只生成内部输入这一项。关联不完整或不一致时不猜测归属。
- 隐藏、ARIA 隐藏、inert 和禁用分组不扫描、不填写。
- 在既有 Moka 重复模块之外，支持有明确标题的 fieldset/role=group 与直接教育、实习、工作、项目记录子项；沿用 RecordCoordinator 整条来源绑定。只点击唯一明确的 type=button 添加按钮，链接角色、禁用分组、隐藏记录或歧义结构降级；原记录被替换或不只新增一条时停止。通用获奖/证书/论文分组保留单项扫描，不冒称已支持其记录角色。
- 完成与占用分开：未确认的下拉搜索不计成功，但仍占用记录，阻止增补和混填。仅新增内存布尔投影 occupied/webOccupied，旧完成快照兼容；不入数据库、备份、AI 或日志。
- “现居住地址”精确关联既有 currentCity；期望、未来或不明确地址不套用。
- 新增真实 React 分步夹具：受控输入、带角色原生选择、异步 ARIA 学校搜索、重复教育、开始年月启用结束年月、联动省市区、返回上一步保留数据；插件不点击步骤或提交。

没有重写已有日期/电话/地区/下拉执行器、模型管线、简历解析、密钥或 Schema。原生控件、真实 React/Vue、Moka、规则学习和重启等已有测试继续保留。

## 人工验收

1. 重新加载扩展，刷新已登录的招聘填写页。
2. 选择测试档案，先扫描核对字段，再填写当前步骤；检查已有内容未被覆盖。
3. 检查学校确实点选、年月与资料精度一致、记录对应正确、地区路径完整。
4. 自行切换步骤，检查前一步状态，再填写当前步骤；不要正式提交。
5. 打开运行日志并导出固定状态诊断。真实平台逐项记录通过、失败、登录受限或待测。
