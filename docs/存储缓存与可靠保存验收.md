# 存储缓存与可靠保存验收

日期：2026-10-28。此为阶段五之后的独立数据层专项，不进入阶段六。分层第 03 步 AdapterRegistry 与文本路径已完成，后续第 04 步暂停，需另获授权。

## 审计与实现

- 扩展设置页、悬浮卡片和旧侧栏通过后台消息访问 `background.js` 唯一 repository；生产代码没有绕过仓库写 `localapply.database`。内容脚本仅得到安全设置投影和已授权单项填写值。`panel/panel.js` 的存储监听只刷新界面。
- `options/standalone.js` 在 `file://` 下另建按目录隔离的 IndexedDB 适配器；每次操作在 Web Lock 内进入自己的仓库队列，明确关闭快照缓存。两种模式不共享数据。
- 设置页字段原来就在 change/失焦后串行保存，保存失败保留脏输入，三方合并和字段级冲突保护有效。本轮没有增加输入防抖、延迟落盘或关闭页刷新逻辑。
- `createRepository(storage, {cache, changes})` 默认不缓存，只有扩展后台显式开启。首次请求读取、完整校验并按原流程升级；队列合并并发首次请求。后续复用已验证 DB，API 配置、凭据密文每次新读，不缓存解密后的 Key。
- 写入流程仍为：队列 → 最新有效快照 → revision/业务校验 → 独立工作副本 → 全量校验 → 必要恢复点 → await storage.set → 发布独立缓存副本 → 成功响应。外部修改返回对象不能污染缓存。没有计时 flush、后台保活、session DB 副本或新权限。
- `onChanged` 只关注 DB/字段目录标记；自身通知以 **排序后前后值的 SHA-256** 辨认，不能仅信 revision 或新值。至多保留 16 个尚未送达的摘要。外部变化释放快照/索引；读期间变化有界重读，提交及恢复点等待期间发现变化则拒绝。超出摘要窗口的旧通知最多导致安全重读。
- 一套引用索引绑定快照身份与 revision，按档案分区字段值/绑定/经历/规则，旧投影使用定义和值索引。`readFieldContext(profileId)` 仅在后台供字段学习读取所选档案，不复制其他档案值、申请或草稿；未新增网页 RPC。显式规则操作仍保留全量规则撤销点。
- 写入失败不发布新副本，允许重读重试；损坏/null/false/未知版本及已知 DB 被外部移除会拒绝，不能当空库重新初始化。Worker 或浏览器退出丢弃内存，重启从持久层校验重建。缓存没有额外持久化格式。
- `storageStatus()` 提供计数、revision、耗时和官方 `getBytesInUse()` 实际占用；诊断页/导出可查看。达到运行时配额的 90% 提示导出备份和检查占用；不删除资料。写入配额错误返回固定可操作提示，日志继续使用既有脱敏机制。

## 兼容性与修复

Schema 仍为 v5；字段/经历/申请、普通及兼容 v3/v4 备份形状、导入预览、恢复点、口令与本机密钥封套保持原契约。迁移仍先验证旧库，恢复点和迁移标记仍沿用现有提交步骤；未将多键 set 当成数据库事务。无新依赖、运行权限或原文件持久化。

发现并修复：

1. 每次读取重复搬运/升级校验全库，及旧 UI 按每字段反复全表查找。
2. 旧投影的多选数组存在引用外泄；现在对外返回独立值。
3. 原来 falsy 的损坏数据库可能被当成不存在；现在明确拒绝，不重建。
4. 首轮真实 Chrome 复现对象键重排误判自身通知；改为规范化摘要并新增单测。
5. 新匹配投影可能使规则撤销点遗漏其他档案；规则写入前读取完整规则并校验同版本，新增跨档案撤销测试。

## 性能对照（真实 Chromium）

全部为合成数据：12 档案、155 定义、1,860 绑定、1,272 值、1,200 规则、200 申请；初始 JSON UTF-8 为 890,175 字节，修改后官方 DB 占用 890,188 字节，两版本相同。单位 ms；p50/p95 为 nearest-rank，冷读/保存/并发各 10 样本、重复读/投影各 30、整进程重启 5 次。较小样本和同机其他测试造成波动，不作固定提升保证。字段上下文旧版使用全库 read，新版使用后台局部接口，不把不同返回体的差异归于纯存储速度。

| 场景 | 修改前 p50 / p95 | 修改后 p50 / p95 | DB get 前 → 后 | DB set 前 / 后 |
|---|---:|---:|---:|---:|
| 冷仓库首次加载 | 51.6 / 59.5 | 48.6 / 66.6 | 10 → 10 | 0 / 0 |
| 连续全库读取 | 52.2 / 66.9 | 3.0 / 4.4 | 30 → 0 | 0 / 0 |
| 旧 UI 字段投影 | 75.7 / 89.6 | 2.9 / 4.2 | 30 → 0 | 0 / 0 |
| 当前档案字段上下文 | 59.0 / 66.9 | 0.8 / 1.3 | 30 → 0 | 0 / 0 |
| 单次保存 | 154.3 / 168.3 | 184.8 / 207.5 | 10 → 0 | 10 / 10 |
| 并发三读一写（按批） | 347.4 / 385.5 | 223.2 / 231.7 | 40 → 0 | 10 / 10 |
| 完整浏览器重启后首次读 | 134.5 / 148.4 | 122.1 / 131.8 | 5 → 5 | 0 / 0 |

正式测量同一活动仓库 **140 命中/1 未命中**、1 次 DB get、20 次 DB set、0 失效/写入失败；加上 10 个独立冷仓库，get 总数从 151 降为 11。5 次完整重启单独统计，不累入活动仓库计数，每次 revision=20 且首次重新读盘。官方总占用 890,364 字节；DB 不因缓存增大。当前版本的字节/指标来自实际 API，旧版无缓存指标，不能伪造旧命中计数。

单次保存确有额外耗时，包含规范化通知校验和独立副本；保留该成本以确保落盘后响应、旧通知识别及返回引用隔离。冷读仍需完整验证，p95 没有收益。索引保留是因为旧投影/局部查询实测有收益；未增加持续后台、文本保存防抖或其他复杂缓存。

原始产物均在 `.browser-tests/`（已忽略）：P0 的 `storage-baseline-node.json`、`storage-baseline-browser.json`，统一最终算法的 `storage-before-acceptance.json` / `storage-after-acceptance.json` 及同名日志。截图 `storage-cache-diagnostics.png` 已人工查看，展示实际占用和脱敏日志。

初始失败均保留在忽略的 `.browser-tests/`：`storage-cache-unit-initial.log`（16 通过/1 失败，清空语义原本保留 null，修正测试预期）、`storage-cache-e2e-initial.log`（2 通过/3 失败/2 取消，通知问题及清理等待）、`storage-cache-e2e-second.log`（5 通过/2 失败，诊断导航写成备份模块）、`storage-cache-unit-full.log`（232 通过/1 失败，新增测试创建档案后未切回活动档案）。首轮完整浏览器 `storage-cache-e2e-full.log` 为 291 通过/3 失败、0 取消/跳过，621.75 秒：文件页抽屉异步读取未结束即断言，随后未关闭抽屉挡住主题按钮；只增加真实可见等待，保留原模态/焦点/草稿/数据断言。未删除旧测试或降低已有断言。测试清理只关闭自己的浏览器、服务和临时目录。

## 范围与局限

结论：P0～P3 和 C01～C16 的本地验收条件已满足。第 03 步后续重构继续暂停，停止于本专项，不进入第 04 步或阶段六；未 stage/commit/push 或创建分支。升级只需重新加载扩展、重开旧管理页并刷新招聘页；无需卸载或安装新运行依赖。撤回本轮代码无需降级 Schema，内存缓存不会改变备份格式；任何个人数据恢复仍走原预览确认流程。

验收使用本机独立 Chromium、合成资料和本地 Mock，不操作用户 Edge/Chrome，不使用真实 Key/简历，不投递。不代表真实 ATS、API 或 Edge 的实站验收。

内存快照和 SHA-256 通知校验增加内存/写入 CPU 开销；保留可靠落盘语义，不能宣称所有操作均加速。完整管理页 `read()` 为兼容继续返回全量副本；只将后台字段学习改为局部投影。未增加 file 模式缓存、云同步、加密方案或存储迁移。

Chrome 存储没有跨任意外部写入者的 compare-and-swap 事务；本项目仍要求生产代码唯一仓库写入。监听能拒绝已经观察到的外部竞态，不能保证抵御绕过仓库在事件送达前直接并发覆盖 DB 的任意第三方。不要把此机制当成多写入者数据库。
