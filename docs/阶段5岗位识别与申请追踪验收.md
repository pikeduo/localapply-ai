### 数据结构与接口

- Schema **v4 → v5** 新增 `applications`，原六张简历表、旧 `ledger`、API 配置、自动密钥和保险库保持原结构。先逐级校验旧版本，再同批写入升级库和恢复点；迁移失败保留旧库。
- `ApplicationRecord`：applicationId、companyName、jobTitle、jobUrl、jobId、jobSource、location、employmentType、summary、status、appliedAt、round、notes、tags、todos、archived、createdAt、updatedAt、history。`history` 仅允许明确用户/导入来源，状态与末次事件一致；每库最多 5,000 条。
- 后台唯一仓库命令 `saveApplication`、`deleteApplication`、`importApplications` 均要求确认和 expectedRevision。`jobs:scan` 只允许当前卡片所属标签；`jobs:submitted/feedback` 不返回个人库，只允许顶层内容脚本上报候选与状态。`jobs:acknowledge` 清理本标签临时提示。
- 独立申请包为 `kind: localapply-applications, schemaVersion: 1`，保留完整历史；拒绝未知属性/版本、损坏日期和可执行 URL。JSON/CSV 都不包含简历、API 配置或 Key；JSON 含用户保存的职位摘要，导出前提示范围。
- `localapply.jobSessions` 只在 `chrome.storage.session` 保存最多 20 条、10 分钟有效的待确认候选，关闭标签后清理，不进入备份。诊断只有固定操作和错误分类，不记岗位/备注/URL/私人值。
- `file://` 申请管理继续使用按目录隔离的 IndexedDB，不与扩展自动同步；岗位扫描仅存在扩展卡片内。零 Key 可以使用全部本地申请功能。

### 迁移、回滚与限制

1. 正常升级自动保留原简历及凭据，完整备份包含 v5 申请表。导入旧备份采用合并时保留现有申请；覆盖前预览申请移除数，并保存恢复点，取消预览不写库。
2. 回滚前保存普通完整 v5 备份、独立申请 JSON，以及目标旧版兼容 v4/v3 备份。兼容 v4 保留多记录结构，兼容 v3 将额外记录转成私有平面字段；两种兼容包均不含申请表，UI 明确提示。
3. 停用当前扩展，在另一目录加载旧版扩展/文件页，在旧版空库导入兼容包；保留当前 v5 库，不让旧代码直接读 v5。回到新版后可导入独立申请 JSON。Key 不进入任何备份，独立旧版需重新配置。
4. 未抽检真实招聘网站、真实模型或 Edge；不能把合成页面通过当成北森/Moka/飞书已全面适配。非原生 submit、跨域成功跳转、非明确状态区的反馈或未识别页面仍需手动记录；插件不会自动投递。岗位 AI 兜底未新增，识别全程为本地规则，现有未知简历字段的可选 AI 不变。
5. 下一阶段为阶段六复杂招聘控件适配和获授权真实站点抽检，需用户另行授权；本次不进入阶段六。

### 手动验证入口

重新加载扩展，关闭旧设置页后重新打开，在“申请追踪”手动新增一条合成记录，检查状态、看板、筛选和 JSON/CSV。无需卸载插件或安装运行依赖。

若需验证成功/失败反馈，可自行在项目目录启动本地静态服务：

```powershell
python -m http.server 8089 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8089/test-pages/phase5-job.html`，在插件卡片确认保存岗位；选择测试反馈并由你本人点击“提交申请（合成测试）”。失败不改状态，成功只提示确认；关闭卡片后再提交成功可检查右下角提示。到“申请追踪”检查去重、新轮次、刷新/重启及导入恢复；本地测试按钮不会发送真实申请。验证后在终端按 Ctrl+C 关闭你启动的服务。
