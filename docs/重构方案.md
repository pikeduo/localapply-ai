# LocalApply AI 重构方案

日期：2026-10-24。分析基线：本地提交 `bbd3368`，扩展版本 `1.3.7`。

本阶段完成源码分析、架构设计和基础测试，不调整生产行为。后续按本文阶段逐步替换；保留根目录 MIT 许可证、`Copyright (c) 2026 xiaoxiaobaijiangjun` 和第三方版权声明。Fork 来源以用户说明及本地许可证为依据，未对上游分支做远端差异审计。

## 1. 结论与产品边界

建议采用 **Manifest V3 + TypeScript + Vite + Vue 3，IndexedDB 本地数据库，Service Worker 统一业务入口，Playwright Chromium 测试**。Vue 仅用于扩展侧边栏和管理页；内容脚本保持轻量 DOM 代码。无需 Python 服务、云端账户、向量数据库或本地模型下载。

保留现有填充引擎作为兼容层，先建立测试和数据边界，再迁移 UI 与学习能力。无需为了换 UI 同时重写 DOM 引擎。

“本地优先”表示存储、规则匹配、编辑、导入导出和已知字段填充均可离线完成。用户选择远程模型时，AI 解析会向该模型发送经过预览的必要文本或扫描页图片；不宣称 AI 完全离线。允许用户配置本机 OpenAI 兼容服务，HTTP 默认只允许明确配置的 loopback 地址。网页表单中的最终提交、登录、验证码、授权协议勾选始终由用户操作。

“不持久化原文件”覆盖 File/Blob、ArrayBuffer、PDF 页面图片、原始全文、解析临时缓存及测试轨迹。生产环境仅持久化确认后的结构化信息、必要证据摘录和非文件内容元数据。内存释放是清理引用及销毁 worker/画布，不承诺 JavaScript 可物理擦除内存。

## 4. 数据 Schema（目标 schemaVersion=2）

IndexedDB 名称 `localapply-ai`，首个新库物理版本 `1`；业务 `schemaVersion=2`，备份 `formatVersion=1`，三种版本各自演进。`chrome.storage.local` 仅存引导状态、非敏感 UI 偏好和迁移指针，并设置 trusted contexts 访问级别；不使用 sync。内容脚本通过受限 RPC 获取设置投影和当前批次值，不直接读取数据库或凭据。

所有持久化记录使用 UUID、ISO UTC 时间和整数 revision；外键、值类型、数量限制在命令层校验，IndexedDB 不提供关系数据库外键约束。

| Store / 主键 | 核心字段 | 索引/约束 |
|---|---|---|
| `meta` / key | schemaVersion、activeProfileId、migration 状态、vault 参数 | 单项配置；版本未知拒绝写入 |
| `profiles` / id | name、createdAt、updatedAt、revision | 不同档案值隔离 |
| `entities` / id | profileId、kind、order、title | `[profileId,kind]`；kind 为 person/education/employment/project/family/contact |
| `fieldDefinitions` / id | semanticKey、label、group、valueType、scope、entityKind、aliases、options、sensitive、autoFillPolicy、origin、revision | semanticKey 唯一；动态字段用 custom UUID，不能把标签当唯一 ID |
| `fieldValues` / id | profileId、entityId、fieldId、value、status、evidenceIds、confirmedAt、updatedAt、revision | `[profileId,entityId,fieldId]` 唯一；status=confirmed/needsInput |
| `evidence` / id | profileId、sourceId、sourceType、page/block、excerpt、fieldValueId、createdAt | 最小摘录，默认每条 ≤300 字；不保存整份简历全文或页面 HTML |
| `sources` / id | profileId、kind、displayName、importedAt、parserVersion | kind=pdf/docx/manual/legacy；不含文件 bytes、base64、可还原文件的 URL |
| `siteMappings` / id | scope、fingerprint、target、optionMap、normalizer、status、confirmedAt、adapterVersion、revision | `scopeKey + fingerprintHash` 唯一；不存字段值 |
| `learningReviews` / id | profileId、candidate、evidenceIds、baseRevision、decision、expiresAt | 待确认值仅内存/session；持久化只存确认/拒绝后的必要决策信息 |
| `modelConfigs` / id | name、baseUrl、protocol、model、visionModel、capabilities、timeoutMs、credentialId | 多端点独立配置，protocol 初期仅 openai-chat-compatible |
| `credentials` / id | configId、ciphertext、iv、keyVersion、algorithm | 只存密文，Key 不返回给内容脚本 |
| `drafts` / id | profileId、questionFingerprint、text、evidenceIds、status、createdAt | 未确认草稿与事实字段严格分开，每题最多 3 版 |
| `fillRuns` / id | profileId、origin、route、adapter、counts、itemStatus、durationMs、createdAt | 不存完整字段值、Key、URL query/hash；限条数并可清除 |
| `materials` / id | profileId、name、note | 仅清单，不含文件 |

`fieldDefinitions.valueType` 支持 text/longText/number/boolean/date/yearMonth/enum/multiEnum/url；空值使用 null，不能用真假判断吞掉 0/false。日期保留精度（不能把仅年份捏造成某月某日）；电话号码、证件号属于字符串。`scope` 区分 global 内置和 profile 自定义；自动填充策略为 auto/manual/never，敏感字段还可独立禁止向 AI 发送。

教育与工作等重复经历通过 entityId 关联：例如两段教育各有 school、major、degree、startDate、endDate，不使用 school1/school2 扁平 key。网页 target 保存 entityKind 和选择策略（如 user-selected/most-recent），执行时解析到当前档案实体；不把另一档案的 entityId 复用。原 `school` 等字段迁为默认教育实体；无法无损拆分的经历长文本保留为 legacy 描述，不强行推断。

### 4.1 API Key 加密与访问边界

- 用户设本地解锁口令，以 Web Crypto PBKDF2-SHA-256 派生 AES-256-GCM 密钥；salt 至少 16 随机字节，每次加密独立 12 字节 IV。迭代数版本化保存、按设备基准校准，初始候选 600000，不能当作不可调整常数。
- 加密认证附加数据绑定 credentialId/configId/keyVersion；持久化口令、明文 Key、解密密钥均禁止。把密钥和密文一起存本地不能实现口令保护，不能以此交付。
- 解锁密钥默认仅在 worker 内存，worker 回收/浏览器重启即重新解锁；首版接受这一交互限制，不假设 MV3 常驻。锁定不影响本地规则填充。后续如需会话保持，单独评审 trusted session 的威胁边界。
- 旧明文 Key 在设置页引导用户设口令后，先写密文并验证可解密，再移除旧 Key；失败则保持旧版本可恢复状态并明确显示未迁移。完整迁移快照不得额外复制明文 Key。
- 设置页只显示“已保存/未保存/已锁定”，不用读取原 Key 来渲染。worker 校验 sender 为扩展可信页面；内容脚本只允许发现/填充/打开面板类消息，不能代理任意 AI、导出数据库或读取凭据。
- 自定义端点保存前校验协议、地址和精确 origin 授权；拒绝携带凭据 URL，跨 origin 重定向不转发 Authorization；请求日志不包含 headers、个人原文或模型原始响应。
- 凭据库保护静态文件中的 Key，不承诺抵抗已解锁扩展被恶意代码控制。简历数据默认本地明文存储并在 UI 遮挡；如后续需要全库加密，应作为独立需求。

## 5. 字段发现、学习与确认流程

1. 发现当前 tab、frame、document、generation 的可见可编辑控件，提取 label、section、ARIA、选项、格式约束；排除密码、验证码、隐藏控件、提交和协议同意等。未知字段仅在用户打开助手或有充分网申上下文时纳入，避免全网聊天框误报。
2. 优先匹配已确认的本站映射，再做平台规则、内置同义词及用户别名匹配。旧评分不是统计概率：初期确定性唯一命中才自动用，近似/多候选/同名重复经历进入待确认；阈值由夹具校准。
3. 未匹配字段显示“待识别”。用户点击“AI 分析”前预览目标模型和本次发送字段描述、选项及相关档案片段；可对本站开启会话内自动分析，但默认关闭并按指纹去重、限制并发/预算，不由 MutationObserver 无限触发。
4. 模型只允许输出 `mapExisting`、`extractSupported`、`createPending`、`abstain` 四类建议，以及 fieldId/valueType、证据 ID/摘录、解释和不确定项。不得返回可执行 selector 脚本、任意代码或网络指令。
5. 服务端入口实际上仍是本机 worker：校验返回 Schema、fieldId 是否存在、证据是否属于当前档案、摘录是否匹配、值是否与证据一致、格式/枚举/长度是否合法。模型 confidence 仅展示参考，不能替代规则验证和人工确认。
6. 无依据时创建 value=null、status=needsInput 的字段建议，明确“简历中未找到，请填写”，禁止从学校/年龄猜政治面貌、婚姻、薪资等。开放题生成属于草稿，不自动变成事实。
7. UI 显示网页字段、拟关联字段/新定义、建议值、证据和作用域。用户可编辑、选择其他经历、拒绝或确认；保存学习与是否立即填入为明确操作。取消/失败/未确认时不写事实字段和映射。
8. 确认命令携带 requestId、tab/frame/document/generation、baseRevision。重新验证页面及档案版本，在同一 IndexedDB 事务中写 fieldDefinition（如新建）、fieldValue（可为 needsInput）、evidence、siteMapping 与确认记录；唯一 requestId 防重复提交。冲突时展示差异，不覆盖新值。
9. 填充执行不在数据库事务内：数据库已确认但 DOM 失效时保留学习并提示重检测；填充成功与学会映射是不同状态。网页换代、控件语义变化、重复匹配时规则标记 stale，重新确认。
10. 下次命中仅使用 confirmed 字段值和有效映射；待填写字段继续跳过。切换档案必须重新解析实体和值，不能复用上一档案填充计划。

本地日志记录任务类型、requestId、数量、耗时、错误码和失败阶段；默认仅短期保留且可清除。证据是业务资料，不应作为调试日志输出。

## 6. 简历导入管线

文件选择 → 类型/大小/页数校验 → 本地提取 → 内容预览及模型发送确认 → AI 结构化解析 → Schema/证据校验 → 逐项校对与冲突预览 → 用户确认 → 结构化事务保存 → 清理临时资源。

- PDF：升级 PDF.js，本地 worker 抽取分页文本和位置；扫描件按需逐页渲染，展示视觉调用次数及发送内容，可取消；无视觉模型时提示手录。并发和尺寸有上限，不一次持有所有高分辨率页面。
- DOCX：使用 Mammoth `extractRawText({arrayBuffer})`，不把转换后的 HTML 直接插入界面，不获取外部关系/图片。首版保存段落级证据，复杂表格抽取不足时提示人工检查；保留多教育/工作/项目结构。
- 初始预算：文件 ≤10 MiB、PDF ≤30 页、抽取文本 ≤100000 字；DOCX 解压累计 ≤50 MiB、条目数 ≤2000，超限在解压阶段终止，不能只检查压缩包大小。文本分块、输出 token 和模型上下文另设预算，不能静默截断造成履历遗漏。
- 失败、取消、关闭或重新选择文件时销毁 PDF task/document/worker、释放 canvas/对象 URL、清空文件 input 和临时引用。候选可存 trusted session 以承受 UI 重开，但不含原始文件/全量图片/全文；关闭会话即清理。
- 不持久化完整原文以提供未来无限抽取。未来未知字段只能基于已确认结构化值及有限证据；缺少依据时要求重新选择文件或手填。

## 7. UI 页面结构

视觉方向：简洁中文、浅灰背景、白色内容面板、单一蓝色强调，统一 4/8px 间距、12px 圆角、14px 正文字号；减少 emoji 和大段常驻说明。状态同时有文字/图标，不仅靠颜色。品牌采用 LocalApply AI，关于页清楚保留上游作者和许可。

### 7.1 侧边栏：完成当前页面任务

顶部：品牌 + 当前档案切换 + 管理入口。主体三个标签：“页面助手 / 我的简历 / 待确认”。底部保留当前档案、模型锁定状态和“仅本地保存”的准确说明。

页面助手自上而下：当前招聘系统/页面 → “可填写 / 待确认 / 缺少资料”统计 → 主要按钮“一键填充 N 项” → 可折叠字段清单（网页字段 ← 简历字段、来源、当前状态）→ 失败与复查。已有非空网页值默认保留，覆盖需显式选择；不能称无回滚数据的操作为可撤销。

待确认卡片：原字段与所属区块、建议含义、可编辑值、证据摘录、新字段开关、本站记忆范围、“确认保存”“保存并填入”“忽略”。空值状态明确显示“待填写”，无依据不预填生成内容。

我的简历：搜索 + 分组概览 + 完整度提示，点击进入编辑；导入入口置于显眼位置。侧边栏不再同时堆放全量设置、附件管理和台账表格。

## 8. 本地备份与版本迁移

备份封套：`kind=localapply-ai-backup`、formatVersion、schemaVersion、appVersion、exportedAt、各 store 数据、可选 checksum。校验和检测意外损坏，不等同于可信签名。

默认导出所有档案、定义、结构化值、证据、映射、材料、非敏感模型配置及用户选择的记录/草稿；默认不含凭据。选择“包含 API Key”时必须用导出口令重新加密为可跨设备解锁的独立 vault，不能原样导出依赖本机内存密钥的密文；可额外选择整份备份加密。

导入顺序：大小限制 → JSON/解密 → kind/format/schema 校验 → 引用完整性/唯一性/凭据绑定校验 → 历史版本内存迁移 → 数量与冲突预览 → 用户选择合并/替换 → 原数据恢复点 → 单事务写入。重复导入幂等；更高未知版本拒绝，不做猜测性降级。映射跨设备导入后标为待验证，避免直接信任旧页面结构。

兼容旧 `wangshen-autofill-backup` version=1 以及原 `chrome.storage.local.wangshenAutofill` schemaVersion=1：保留档案 ID/值/自定义定义/材料/台账/自动填充意图；标准 key 建明确映射表，包含 graduation → education.endDate。原备份仅含档案，不能声称能恢复不存在的设置/台账。无法识别的字段保留到 legacy 分组，不静默丢弃。

IndexedDB 升级事务只做本地结构变更，不能等待模型请求或口令输入。迁移启动先生成不含额外明文 Key 的恢复点，使用稳定 ID 可重试；确认新库条数、抽样值和引用完整性后切换 active 指针。旧数据保留到用户确认迁移成功再清除，旧 Key 单独按凭据迁移策略处理。跨页连接收到 versionchange 主动关闭，blocked 明确提示关闭旧管理页。

## 9. 平台兼容策略

通用发现 + 独立平台适配器，共享填充执行器；不把平台判断扩展成一串散落的 if。适配器提供 match/detectContext/discoverExtras/resolveOptions/readBack 等有限能力；匹配同时考虑域名和页面特征，不仅依赖域名。

| 平台 | 首要覆盖 | 证据与边界 |
|---|---|---|
| 北森 | 深层标签、空 placeholder、区号/手机号、日期范围、重复教育、虚拟下拉、iframe | 先收集公开申请页或用户授权的脱敏结构；当前仅有通用逻辑的相关注释，不能当作已完成适配 |
| Moka | 现有字段/自动补全、portal 下拉、异步选项、学校专业实体选择、重渲染 | 保留 moka-mock 和补全夹具；增加真实组件结构，不把旧模拟页当真实站点成功率 |
| 飞书招聘 | ARIA combobox/listbox、自定义组件、多选、重复经历、SPA 多步 | 新增脱敏 fixture 和状态断言；自定义域名采用特征识别并限制作用域 |
| 国聘 | Element UI 标签/选项、家庭成员隔离 | 维持现有回归，不因重点平台新增而退化 |
| 通用 | input/textarea/select/radio/checkbox/contenteditable、open shadow、授权 iframe | closed shadow 无可用 API 时明确手动；跨域 iframe 未授权时提示授权 |

填充计划绑定页面版本与控件身份，执行前检查连接、可写、现有值和类型，执行后等稳定状态/校验反馈。日期控件、级联地区、虚拟列表使用专门适配；歧义停止，不扫全页随便点第一个文字相似元素。任何路径都不点击提交或自动同意协议。

## 10. 测试体系及依赖

现状无 package.json、锁文件、Playwright 或单元测试框架；运行扩展无 npm 依赖。工具用 Node 内置 API，旧验收另依赖 Windows Edge、Python 标准库、自签 HTTPS 证书、8321/8399/9222–9224 固定端口和全局 WebSocket。Node 版本要求此前未声明。

旧 `tools/verify.js` 有 40 处 report 调用，其中 1 处真实 PDF 条件执行；README 的“35 项”已不准确。受控组件夹具只是原生 JS 模拟，不是真 React。AI 成功返回、DOCX、字段学习、备份往返、并发写入、迁移失败、北森/飞书、真实页面均无完整验收。

新测试分层：

- 单元：沿用 Node test 做纯函数测试，必要时用 TypeScript 编译结果执行；覆盖规范化、数据校验、字段决策、导入冲突、加密/解密和无依据拒绝。
- 集成：Chromium 扩展 origin 内测真实 IndexedDB、storage、worker 消息权限、跨管理页写入冲突、事务回滚、重启迁移、导出再导入。不能只用内存数据库替代最终门禁。
- E2E：Playwright `chromium.launchPersistentContext`，随附 Chromium，唯一临时 profile；从实际 worker URL 动态取扩展 ID。打开扩展页面验证 UI，同时单独验证真实 sidePanel API，不能把普通 tab 当真实侧栏证明。
- 页面夹具：保留全部旧用例，增加真实 React/Vue、北森/飞书控件、多经历、open shadow+light 混合、同/跨域 frame、异步 portal、路由切换、DOM 重建、未知单行字段和有值保留。
- 模型夹具：用受控 loopback 假 OpenAI 兼容服务，检查请求最小化、格式错、无证据、401/429/5xx、超时、取消、提示注入。worker 网络请求不要仅依赖页面 route 拦截；假服务清楚记录调用次数但不存个人原文。
- 安全行为：在 fixture 捕获 submit、requestSubmit、提交按钮/链接、协议勾选和网络请求；断言为零。静态正则不能代替运行时断言。针对 portal 误点击、恶意模型输出和跨档案规则污染专项回归。
- 隐私：完成/取消/失败/重启后检查 IndexedDB、local/session storage、CacheStorage、日志及下载内容，不得残留原文件、完整全文或明文 Key；测试只用合成资料，轨迹失败保存且可控清理。
- CI：首次失败保留 trace/截图/结构化报告，普通成功不保留敏感工件；无真实 API Key、无外部站点网络。真实 ATS 人工抽检作为单独清单，不能阻塞可重复的离线回归。

实施时新增并锁定：TypeScript、Vite、Vue 3、Zod、idb、pdfjs-dist、Mammoth；开发测试加 @playwright/test、必要的 Vue Vite 插件。安装版本以实施日官方兼容性核验和锁文件为准。依赖安装和浏览器下载本阶段未执行；Chromium 下载由用户手动执行。不新增 Python 环境。

阶段一落实 package 脚本后，用户执行：

```powershell
npm ci
npx playwright install chromium
npm run test:unit
npm run test:e2e
npm run build
```

上述 npm 命令是未来约定，目前仓库没有 package.json；本阶段可立即执行的是：

```powershell
node --test --test-timeout=20000 tests/baseline.test.cjs
```

新增依赖/测试产物时同步 .gitignore：node_modules/、playwright-report/、test-results/、临时 profile、覆盖率、.env；dist 已忽略。测试源文件和合成夹具必须提交。浏览器测试不杀其他端口进程，端口占用时换端口或清晰失败；只关闭自己持有的 context/server，并在删除临时目录前验证绝对路径属于测试根。

每阶段独立可回归、可审阅，不自动 stage/commit/push，不混入无关清理。以下均为计划，只有阶段零已完成。

| 阶段 | 交付 | 完成门槛 |
|---|---|---|
| 0 分析与基线（本次） | 本方案、测试记录、无依赖测试 | 14 项基础测试通过；清楚区分浏览器未测和代码审查发现；生产代码及许可证保持不变 |
| 1 工程与回归底座 | Vite/TS 多入口、Playwright、旧逻辑兼容层、关键旧缺陷回归、PDF.js 升级 | 构建后扩展实际加载；旧通用/Moka/国聘/受控模拟/登录/孤文本/补全行为逐项等价；毕业时间导入后可填；连续 3 次运行无重试全通过；只清自己资源；源码及发行包含许可证 |

| 3 中文 UI 与简历 | 新侧边栏/管理页、PDF/DOCX、证据和结构化多经历 | 两种文件都走真实选择→提取→假模型→校对→确认；确认前不写事实；重复经历不压扁；失败/取消无原文件持久化；360/400/480px 及键盘流程检查通过 |
| 4 字段学习闭环 | unknown、四类建议、人工确认、事务学习、规则管理 | 未知单行字段可见；有证据建议可确认；无证据值保持空；拒绝无写入；确认定义/值/映射原子保存；刷新后离线复用；跨档案/站点/区块不误用；页面变更拒绝旧计划 |
| 5 ATS 深度适配 | 北森/Moka/飞书适配器及国聘回归 | 每平台至少 3 类脱敏表单夹具，涵盖 ≥30 个可填逻辑控件；声明支持的固定夹具识别召回率 ≥95%、自动填入准确率 100%、不得误点击；重复经历/异步选项/重渲染有状态验证；真实站点每平台至少 2 个申请流程由用户授权人工核对，未取得样本则标明真实兼容性未验收 |
| 6 备份迁移与发布候选 | 完整导出导入、历史版本矩阵、构建包、隐私文案 | 完整往返保存引用/结构化值/规则/配置；合并幂等、替换可恢复；损坏/超大/未来版本拒绝；含凭据备份跨测试 profile 可解锁；连续 3 次完整离线 E2E 通过；发行包不含测试证书/Key/简历/日志，完整许可核对通过 |

阶段 5 指标只针对有明确 ground truth 的受控夹具：召回率=发现的应填逻辑控件/全部应填逻辑控件；准确率=正确自动填写项/所有自动填写项，空值/验证码等不入分母，另记录跳过率，防止通过全部跳过伪造 100%。不能宣传这些数字为真实招聘网站总体兼容率。

每阶段统一门禁：不自动提交、不自动同意协议、不伪造简历事实、未确认不学为正式规则、无跨档案污染、无需 Key 的核心流程可用、数据不因迁移或 UI 切换静默丢失。先交付阶段一回归底座，再引入数据库和 UI；避免把新旧行为混在一次大重写里。
