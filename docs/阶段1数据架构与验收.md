# 阶段一：本地数据架构与字段体系

日期：2026-10-24。以用户最新阶段一需求为验收依据。

## 阶段调整

阶段零原计划先做 Vite/TS/Playwright 工程底座，再做 IndexedDB。本阶段按用户新要求，优先实现数据架构、采用 chrome.storage.local，复用现有原生 JS/页面/识别与填充代码。只增加必要的数据管理 UI 和 Playwright 验收，不引入 Vue/Vite，不自动进入下一阶段。

## 存储与 Schema

| 本地 key | 作用 |
|---|---|
| `localapply.database` | schemaVersion=2、revision、规范个人库 |
| `localapply.apiSettings` | provider、model、visionModel、customBase、apiKeys，独立于个人库 |
| `wangshenAutofill` | 保持原样的旧迁移源；不再写入，也不自动删除 |
| `localapply.recovery` | 最近一次导入前的个人库快照；不含 API 配置 |

个人库包括：

- `fieldDefinitions`：FieldDefinition 白名单 fieldId/label/type/group/aliases/options/description/version，绝无 value/profileId。内置定义复用原模板；私有新增使用 UUID，旧备份私有字段使用稳定标识以支持重复合并。
- `fieldValues`：ProfileFieldValue 使用 profileId/fieldId/entryId/value/updatedAt/source。复合键唯一，entryId=null 为旧平面字段；0/false 保持真实类型。
- `entries`：entryId/profileId/kind/title/order，kind 为 education/internship/employment/project；每类可多条，每条独立字段值。
- `bindings`：每档案的展示 fid、旧 key、敏感标记和自动填写策略；不属于公共元数据，不导入公共包。
- `profiles`：档案名称、ID、创建时间、材料名和备注。
- `mappingRules`：mappingId/origin/path/label/fieldId/profileId/entryId；全量本地备份包含规则，公共字段包不包含规则。
- `publicFieldIds`：已经审核允许导出的定义 ID。默认内置字段；个人新增和迁移自定义字段默认不公开。
- 填充设置、活动档案、引导状态、原台账和草稿继续本地保存。

当前字段类型：text/textarea/select/number/boolean/date/multiSelect。新值检查字段、档案、经历引用；经历不允许引用其他档案的值。定义版本递增，类型变化若无法兼容已有值则拒绝，不静默丢弃数据。

## 后台 API 与兼容

仅可信扩展管理页/侧栏可调用个人数据、备份、命令和模型入口，验证 sender.id 和精确扩展页面 URL。`chrome.storage.local.setAccessLevel({accessLevel:'TRUSTED_CONTEXTS'})` 在读写前完成；内容脚本只能调用 `wsa:contentSettings` 获取 autoThreshold/privacyMask/autoFloatbar，设置变化由后台广播安全投影。

`LocalApplyStore.createRepository(storage)` 接口：

| 方法/命令 | 说明 |
|---|---|
| initialize/read/readLegacy | 初始化、规范库读取、旧 UI 投影 |
| saveLegacy(base,next,source) | 三方合并差异，同字段并发冲突拒绝 |
| createField/editField/deleteField | 动态字段新增、版本编辑、删除与引用清理；可供以后 AI 确认流程调用 |
| createProfile | 独立档案，新档案不复制其他人的值 |
| createEntry/deleteEntry/setValue | 重复经历及类型化个人值 |
| saveMapping | 仅本地映射规则接口，尚未连接字段学习 |
| exportBackup/previewImport/importBackup | 完整资料备份、合并/覆盖差异预览、带 revision 确认提交 |
| restoreRecovery | 恢复最近一次导入前资料，不改变 API 设置 |
| publishDefinition | 接受单独审核的公共定义，不能自动公开原私有字段 |
| exportPublicFields/mergePublicFields | 元数据白名单导出、版本化合并；无 GitHub 请求 |

所有操作通过后台队列串行；写入前操作克隆副本并校验完整引用，再写单个个人库 key。这里不宣称 Chrome Storage 提供跨 key 数据库事务。API 配置先独立迁移，个人库 key 为迁移生效点。新导入保存恢复点后才写新库；配额/写入失败返回错误，保留当前资料或恢复点。

旧页面通过 common.js 的快照差异保存接入，未再直接 storage.set；不同字段的并发修改可合并，同字段拒绝并提示刷新。个人值变化不会更新公共定义。保留了原 detector/filler 逻辑，只有内容脚本配置读取改为安全消息；PDF 毕业时间 key 与原词库对齐为 graduationDate。

## 迁移和恢复

1. 没有新库时读取旧 wangshenAutofill；没有旧源才创建默认空档案。
2. 校验旧 schema；拆分 API 配置、档案、字段定义、个人值、开关、材料、草稿与台账。
3. 不自动调用会重置 autoFill 的旧 upgradeProfile，保留用户已有禁用设置；同 key 的重复字段也保留各自值。
4. 私有定义默认不进入公共字段包；特殊经历长文本保持原样，不靠猜测拆分。
5. 先写独立 API 设置，再写新个人库，并读回验证；旧源始终原样保留。失败重新启动可重试，不以空数据覆盖。
6. 有新库后只读新库，重复启动不生成重复字段。旧格式备份的自定义 ID 稳定，反复合并不重复。

若迁移本身失败，旧数据仍可由旧版扩展读取；修复错误后重试即可。若导入后需要撤回，设置页“恢复到导入前”使用最近恢复点。此操作恢复个人库，不改 API 配置；恢复点不是多版本历史仓库。

## 备份与公共字段包

完整备份使用 kind=localapply-ai-backup、formatVersion=1、schemaVersion=2、exportedAt、database。默认不导出任何 API 配置/Key，不导出旧源和恢复点，也不导出原简历文件。

导入前校验 JSON/大小（8 MiB 上限）、字段类型、额外键、重复 ID、引用和版本，显示新增档案/字段/值、冲突、移除档案数量；合并冲突保留当前数据，覆盖需显式选择。确认提交必须携带预览 revision，期间数据变化会拒绝。支持 wangshen-autofill-backup version=1；未来版本拒绝，不猜测降级。

公共包使用 kind=localapply-public-fields、version=1、fields。只输出白名单元数据，不包含档案、值、API、规则、记录或私有标签。接收公共包只建立定义和空白展示绑定，不复制 fieldValues。版本较新时更新公共元数据而保留个人值，同版本不同内容拒绝；导入包永远不能覆盖本地私有定义。

导入私人备份不会提升新字段的公开权限；只保留本机已审核且元数据相同的范围。换设备导入后，新公共定义也须重新通过公共包审核/合并，防止备份通过 publicFieldIds 把私人标签混入后续公开导出。

公共元数据本身仍需人工审核名称/说明是否夹带私人信息；系统不可能仅凭任意文本判定一个标签是否包含某个人的真实资料。因此自定义字段默认私有，publishDefinition 必须提交独立审核的新定义，而不是一键把个人字段原样发布。当前没有上传网络接口。

## 页面操作

- 原侧边栏继续管理平面字段、档案和自动填表；旧数据升级自动发生。
- 设置页“数据与隐私”支持完整导出、文件选择、合并/覆盖、差异预览、确认导入和恢复点。
- 公共包可本地导出和合并；新字段默认不参与自动填充。
- “重复经历”按档案和四类经历创建多条，选择定义、输入值并保存；支持删除经历。当前网页重复区块自动填充尚未实现，界面已明确提示。

## 验证

```powershell
npm test
npm run test:e2e
```

依赖准备由开发者手动执行 `npm ci`、`npx playwright install chromium`。仅生成锁文件不会下载浏览器。测试使用合成资料和假 Key 标记，不涉及真实简历、外部 AI 或 GitHub。

`npm test`：**34/34 通过，退出码 0，约 1.1 秒**，覆盖原基础 15 项和数据层 19 项。PDF.js 缺少可选 canvas 的 DOMMatrix/Path2D 警告仍存在，本次不做页面渲染，未安装 canvas。

真实浏览器使用 Playwright 1.62.1 配套 Chromium，实际关闭 context 对应的整个浏览器并从同一独立 profile 重新启动，逐记录比较规范数据库。覆盖：真实旧源迁移、侧栏字段新增/编辑值/删除、四条教育/项目记录、内容脚本存储/RPC 隔离、generic 赋值和无提交、受控组件模拟/Moka 补全/国聘/登录/孤文本、JSON 实际下载与导入预览确认、进程重启持久性，以及页面未捕获错误检查。

浏览器最终结果：**9/9 通过，退出码 0，约 17.4 秒**（一个主测试和八个子测试），没有跳过项；业务验收无未通过项。模拟资料与浏览器临时目录由测试清理。

首次浏览器尝试用本机 Chrome 失败于扩展侧载；后由用户安装配套 Chromium，沙箱启动曾返回 EPERM，获得沙箱外测试授权后正常运行。首次业务测试还有一个测试等待问题（折叠 select 的 option 应等待 attached 而不是 visible），已修正。这些失败没有触碰用户日常浏览器或资料。

数据层回归中发现并修复：旧备份动态 ID 不稳定、旧 UI 新增字段默认 options 不一致、对象属性顺序引发伪冲突、类型化值在旧 UI trim 报错风险，以及旧 API 单 Key 和多 Key 共存时的保留问题。

额外执行 `node tools/package.js` 并使用 Python 标准库检查 ZIP：22 个运行文件，包含新数据层和管理页脚本；LICENSE 与根文件逐字节相同；不包含 tests/test-pages/tools/node_modules。产物位于已忽略的 dist 目录，未上传或发布。

## 已知边界与下一阶段建议

- API Key 已与个人库分开并限制内容脚本访问，但仍本地明文；旧只读源也保留原 Key。后续凭据加密需单独迁移/口令设计，不能宣称本阶段已加密。
- chrome.storage.local 有配额，旧源+个人库+恢复点会增加占用；写入失败必须处理，当前不自动请求 unlimitedStorage，也不偷偷删除旧源。大体量后续再评估 IndexedDB。
- PDF.js 3.11.174 的既有安全风险尚未升级，DOCX 解析仍未实现；本阶段只保证数据库不存原始文件。
- 新增的重复经历和映射数据接口尚未用于网页重复区块学习/填充；原平面字段路径继续工作。真实 ATS 兼容性不能由本地 mock 推断。
- 下一阶段建议先升级 PDF 解析依赖、实现凭据加密，再接入 AI 结构化解析/确认和动态学习流程；本阶段结束后停止，不自动执行。
